# Repair & audit report — v0.3.0 (29 Oct 2026)

Scope: the brief in `docs/REPAIR_BRIEF_2026-10-29.md` (an external review of v0.2.0 at https://liftcircle.netlify.app).
All work is in the existing project. It used additive migrations and focused edits to readable source only: no
regenerated app, no edits to built bundles, and no production data touched.

**Labels:**

- **Reproduced defect**: the failure was shown on the pre-fix code, either by a test, a script or the live site.
- **Source-confirmed concern**: the problem was read in the code but not run.
- **User requirement**: a requested change, not a bug.
- **Passed check**: the behaviour was already correct and was tested.
- **Blocked verification**: the check needs something this environment doesn't have.

Severity: **H** high, **M** medium, **L** low.

## 5. Deployment (not done: needs the owner)

Applying migrations to the production database, redeploying a function and uploading the site are production
deploys. The safety rules in this environment refused them for me, so they're packaged for you instead:

1. **Database:** open the SQL editor, paste all of `deploy/2026-10-30_migrations.sql`, then Run. It is one transaction
   with four additive migrations, and each is recorded in `supabase_migrations.schema_migrations`. If it fails,
   nothing changes. It doesn't touch any existing rows.
2. **AI function:** Edge Functions → `ai-coach` → replace the code with `supabase/functions-bundled/ai-coach.ts` →
   Deploy. Keep **Verify JWT** off: the function verifies tokens itself, and the project uses ECC signing keys.
3. **Site:** drag `liftcircle-site` (or the zip) onto the Netlify site's Deploys page.

**After deploy:**

- Rerun `tests/live/schema-fingerprint.sql` in the SQL editor. The `fn` row must read 170 / `b8b7412d…`.
- Open the AI coach, send "I can only train twice this week", and check you get an **Apply to this week** card.
- Open DevTools on the live site and look for "Refused to…" CSP messages.
- Optionally, create test accounts and run `tests/live/backend-live.mjs` (see `tests/live/README.md`).

## 6. Remaining limits (honest list)

- The live AI model's behaviour (style, two-sessions case) is unverified. Every AI test used a mocked provider.
- Guest → account import has no keep/replace choice for settings (this is disclosed in its preview).
- A client's own custom exercises in a plan stop a coach from revising that plan.
- Signed media URLs stay valid for up to 300 s after access is revoked.
- The server still accepts 0-rep completed sets for older devices (the client never counts them).
- Meal-plan balancing is greedy, with 11 curated protein sides.
- "Small adjustments" in week plans are advice only; session content isn't changed.
- Without IndexedDB the app warns but cannot save.
- Physical-device checks and screen-reader checks haven't been done.
